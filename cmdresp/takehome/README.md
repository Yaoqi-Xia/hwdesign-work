# Configurable Q1.15 FIR

Read `prompt.md` for the specification and `results.md` for the measured
results, assumptions and remaining workflow items. All evidence paths are
relative to this folder, which can be copied or cloned independently.

## Reproduce

Use Python 3.12 with the course Waveflow clone installed in editable mode,
NumPy, mcp 1.x and vcdvcd. Put Vitis/Vivado on PATH and make the server's
license available. This run used Vitis 2026.1; the course requests 2025.1.
The committed C++ includes were generated by Waveflow and make the HLS
sources self-contained even without Python generation.

```bash
python3.12 mcp_smoke.py
python3.12 build.py --through python
python3.12 build.py --through cosim
python3.12 export_trace.py
python3.12 measure.py
```

The default build runs Python, C simulation, synthesis and then one HLS
co-simulation invocation covering every activation. To resume a completed
build use `--stage csynth` or `--stage cosim`. The waveform helper replays the
already elaborated XSim snapshot to export a VCD, without invoking HLS
co-simulation again. `measure.py` checks actual RTL handshakes and startup
status strobes, and reads the original HLS latency and synthesis reports.
It does not create a Python performance model.

For C simulation alone use `python3.12 build.py --through csim`.
`run.tcl` can also be run with `CMDRESP_STAGE=csim`, `csynth` or `cosim` and
`vitis-run --mode hls --tcl run.tcl` after the Python preparation.

## Files

- `model.py`: Waveflow message schemas and an untimed, exact reference.
- `scenarios.py`: deterministic normal, malformed and recovery activations.
- `accelerator.cpp`, `accelerator.h`: synthesizable kernel.
- `tb_accelerator.cpp`: one kernel call per activation; every actual beat
  and status is written to CSV and compared with Python vectors.
- `build.py`: Waveflow support/schema generation, vectors, tool invocation,
  exact comparisons and copying the raw reports.
- `vectors/`: all input beats and expected output/status, in text and JSON.
- `evidence/`: actual outputs, comparisons, tool logs, raw reports,
  compressed VCD and handshake timestamps. `history/` records the reviewed
  first implementation and its startup-clear defect.

CONFIG and DATA produce responses only after their entire input burst
validates. The host must send the entire burst without waiting for a
response and consume responses concurrently with input submission. An error
requires resetting the complete stream path before restarting.

Clock estimates and simulation clock periods are different measurements:
a functional RTL simulation at 10 ns does not prove timing closure at 10 ns.
Read the FAIL recorded against the estimated clock in `results.md`.
